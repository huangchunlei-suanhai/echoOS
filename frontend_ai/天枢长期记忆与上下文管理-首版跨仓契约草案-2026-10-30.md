## 1. 目标、边界和关键决策

首版把“长期记忆”定义为：同一已认证用户的同一会话，在刷新页面、重连和服务重启后，可读取完整的**用户可见**聊天记录（包括已受理的运行中追加指令及其处理状态）；AI 仅从该会话历史选择有限内容进入新请求，并按模型输入预算裁剪。它不等于跨会话画像、全局知识库或任务工作区检查点。

| 项目 | 首版拟定 | 原因与边界 |
| --- | --- | --- |
| 身份权威 | Java 登录；Java 签发会话限定、单次使用的 AI WS 短时票据；AI 经独立认证的内部接口消费 | 浏览器消息体 `user_id` 不可信；握手票据不替代每次受理的登录有效性检查。 |
| 产品数据真源 | Java PostgreSQL 独占管理聊天会话、请求、追加指令、消息和事件事务；前端从 Java 读历史；AI 经受保护接口读写 | AI 任务工作区独立保存执行状态和工程产物；两边**没有跨服务原子事务**，以补偿、扫描和阻断完成处理差异。 |
| AI 先行验证 | AI 先做强类型存储/身份端口、状态机、Context 选择和预算；用 Fake Java、临时 SQLite/目录及假模型验证 | 临时库只在测试或本地联调用；生产缺真实验证器/Java 客户端时启动失败。 |
| 部署与活跃请求 | 首版只允许一个 AI 进程和一个共享、持久的工作区根；独占进程锁 + 持锁递增的 lock_generation + Java writer_epoch + 启动扫描收敛 | 禁止多 worker、重叠滚动发布或各实例各用本地锁目录；多 worker 另行设计 Java 租约/心跳/fencing。 |
| 并发 | 一个会话至多一条 accepted/running 主请求；其他主请求返回 session_busy；运行中 chat_steer 归属该请求 | Java 事务保证单活跃；进程内队列只是运行优化，不是可恢复事实源。 |
| 持久事件 | 只记录消息创建/修订、请求/追加指令状态和白名单进度摘要 | 原始工具 payload、调试事件不进入聊天账本。 |
| 保留 | 不自动过期；支持主动删除会话 | 备份清理另有策略，不宣称立即从备份消失。 |

上轮讨论曾以 AI SQLite 为默认；本草案保留 Java PostgreSQL 作为**拟议生产边界**。架构视角复审允许 AI 后端按此方向先行本地验证，生产接口仍待三仓联调。首版暂不做跨会话语义检索、向量库、自动用户画像、真实 token 流、完整工具时间线回放或自动接管中断任务。历史卡片只保证文本、澄清问题、终态和校验后的任务/操作引用，首版保持只读；审批和继续执行必须进入实时任务界面重查状态与权限。

## 2. 现状依据与目标依赖

- 前端 `AiAssistantWorkbench.vue` 的 `customMessages` 在组件内存；`aiSessionWebSocket.js` 用 sessionStorage 生成 `web_session_*`，当前 `new WebSocket(this.url)` 不带认证；正式联调协议 v3.1.0 明确无通用历史接口。
- Java `TokenInterceptor` 从 token Header/参数校验 Redis 登录信息并设置 `RequestContext.userId`；新内部接口必须有独立服务认证，不沿用浏览器 Token。
- AI Gateway 在 `ws_broker.connect` 前未查会话归属；`chat_start`/`agent_command` 仍接收客户端 `user_id`。pull 后新增 `chat_steer`：`ChatSteerMessage` 接收 `request_id/user_id/prompt`，`UserInputInbox` 在内存生成 `input_id` 并排队，当前 `chat_steer_ack` 未经落盘。断连取消连接任务；静态 Bearer 中间件不能证明 Java 用户身份，`.env.example` 仍是 `ENABLE_AUTH=false`。
- `RuntimeCoordinator` 仍创建 `InMemorySessionMemoryStore`；成功后才追加短期记忆。现有 `PromptContextBudget` 4,000 与对话压缩默认 262,144 是两段独立估算，不是最终模型输入总限额。
- `TaskWorkspaceRepository.create()` 已落 `.task_state/<task_id>/task.json`，元数据含 `user_id/session_id/request_id/goal/artifact_root`；还可能有 `checkpoint.json`、`assistant_messages.jsonl`、`events.jsonl` 和独立的 `.scene_approvals`。AI 仓库根当前没有 Dockerfile 或 docker-compose.yml；Gateway 未注入 `agent_workspace_root`，Runtime 默认 `.var/agent_workspaces`。部署前须明确配置实际持久根及其独占锁，不得假设已有 /data 挂载。

目标依赖：浏览器 → Java 公共身份/历史 API；浏览器 → AI WS；AI Gateway → RuntimeCoordinator → Engine/Capability；RuntimeCoordinator 注入会话账本与身份端口，Java HTTP 适配器在 integrations；ContextPipeline/PromptContextBuilder 选择和投影历史。Capability 不直接访问 Java 数据库、解析 WS 报文或决定身份。Java 账本与 AI 工作区分别为产品可见记录、任务执行状态的事实源，不共享事务；任务 ID 先向 Java 预登记，再创建本地目录；登记失败不得写任务文件。

## 3. 身份与会话创建链路

1. 前端继续用 Java 登录 Token 调 Java 公共 API。Java 认证后创建全局唯一 `session_id` 并写 `owner_user_id`；浏览器不得自行创建正式会话 ID。
2. 前端请求该会话的 WS 票据。Java 验证归属与登录状态，生成随机不可猜、单次使用、建议 120 秒有效的票据，在 Redis 绑定可信用户、会话、过期时间和登录会话引用。票据采用 URL 安全随机编码；长度上限须在三方固定，首版建议不超过 512 个 ASCII 字符，超限在握手解析前拒绝。Origin 缺失或不在显式允许列表时拒绝浏览器连接。
3. 前端用 WebSocket 子协议 `tian-shu.v1`、`ticket.<票据>` 传票据；AI 在 accept 和入广播中心前校验允许的 Origin，并通过独立服务认证的 Java 内部接口原子消费票据、核对 URL 会话。AI 只选择 `tian-shu.v1`；票据不入 URL、业务帧、localStorage 或日志。反向代理、APM、异常日志与 WS 握手审计均须遮蔽整个 `Sec-WebSocket-Protocol` 票据项；内部 API 的服务凭据也须脱敏。
4. AI 连接绑定可信身份；`chat_start`、`chat_steer`、`agent_command`、`chat_cancel` 不再携带可用于授权的 `user_id`，正式协议移除此字段。Java 每次内部读写校验服务身份、可信用户与会话归属；新主请求与追加指令受理时重查登录会话有效性。
5. **登出策略**：前端立即关闭 WS 并清除本地会话缓存；Java 登出使票据与登录会话失效。AI 对输入、持久事件发送前核验登录，连接存活期间定期（建议不超过 15 秒）检查；鉴权服务不可达时停止接收新输入和发送敏感事件并关闭连接；登录失效即关闭 WS 并取消已运行请求，按第 6 章收敛为 cancelled/interrupted，工程副作用可能存在时标为 unknown。只凭浏览器主动断连不构成服务端撤销。登出后新请求、追加指令与删除操作必须重新认证；原会话内容待重新登录后仍按原权属可查。票据自然过期本身不打断已验证的连接。

仅显式 test/local 模式可注入 FakeTicketVerifier 和临时账本；未声明环境按生产模式处理。正式环境若缺真实票据验证器、Java 账本客户端、服务认证或持久工作区/独占锁配置，启动即失败，且不能以 `ENABLE_AUTH=false` + 客户端 `user_id` 对外部署。新增伪造用户、跨会话、票据重用/超长、非法 Origin、日志脱敏、登出前后状态测试。

## 4. 持久数据与可见事件

Java 新建独立聊天表，不改计算任务的 `task_message_log`。具体 SQL 由 Java 负责人实现，以下为强制语义及唯一约束：

| 实体 | 必需字段/约束 | 含义 |
| --- | --- | --- |
| ai_session | session_id、owner_user_id、title、created_at、last_activity_at、state、next_sequence；session_id 唯一 | state 为 active/deleting/deleted；Java 生成 ID；列表按 last_activity_at、session_id 倒序。 |
| ai_request | session_id、request_id、kind、payload_digest、status、writer_epoch、user_message_id、assistant_message_id、task_id、created_at、updated_at、error_code、side_effect_status；(session_id, request_id) 唯一 | kind 为 chat/command；digest 覆盖规范化完整请求，包括 chat 的 prompt/ui_context/access_mode 或完整 command；不保存原始 ui_context。活跃状态由事务/约束限制一个会话一条。 |
| ai_user_input | session_id、request_id、input_id、message_id、payload_digest、status、created_sequence、updated_sequence；(session_id, input_id) 唯一 | 仅用于 chat_steer；status 为 queued/consumed/unapplied；digest 覆盖 request_id 与规范化 prompt；同 input_id 异内容返回冲突。 |
| ai_message | message_id、session_id、request_id、input_id(可空)、role、content、status、revision、created_sequence、updated_sequence、created_at、updated_at、display_view；message_id 唯一 | 原始用户消息为 final；追加用户消息为 queued/consumed/unapplied；助手消息为 pending/partial/final/failed/cancelled/interrupted；同一主请求助手消息只用一个稳定 ID。 |
| ai_session_event | event_id、session_id、sequence、request_id、input_id(可空)、event_type、message_id、message_revision、message_view、safe_summary、created_at；(session_id, sequence) 与 event_id 唯一 | 会话统一单调序号；消息创建/更新、请求及指令状态变更与白名单进度写事件。消息变更事件保存安全可见快照，供补拉更新 UI。 |
| ai_session_task_ref | session_id、task_id、owner_user_id、created_at、cleanup_state；(session_id, task_id) 唯一 | **创建本地目录前预登记 task_id**；不得等 terminal。只作删除索引与经授权引用验证，不存绝对路径。 |
| ai_runtime_writer | deployment_id、lock_generation、boot_id、writer_epoch、activated_at；deployment_id 唯一 | Java 只接受更大的持锁 generation 并递增 epoch；同 generation/boot_id 在当前代次重试幂等，较旧 generation 拒绝。 |

Java 在单事务中锁定会话行分配 sequence；回滚不公开事件和可见空洞。所有受理、读取、补拉、取消、任务登记和删除按可信 user_id/session_id 双重校验；内部调用还校验独立服务凭据。原始系统提示、内部推理、密钥、完整工具参数/结果、完整 `AgentResponse`、原始 ui_context 与绝对路径不得入聊天表。用户原文与最终助手可见文案允许入库，仍受产品数据保护政策约束。

`chat_steer` 的 `input_id` **由前端在首次发送前生成并在重试时保持不变**；AI 不再在内存队列中临时生成授权意义上的 ID。Java 先在一个事务里写 ai_user_input、用户消息和事件，再返回 ACK 所需 ID/sequence；AI 再入本地队列。queued 只表示持久受理，**不表示模型已经采纳**。将其选入下一次模型调用输入时先提交 consumed 状态/消息修订与事件；consumed 仅表示选入待提交输入，不证明供应商已收到。completed 终态须确认该指令实际进入模型调用尝试。请求终态事务把仍 queued 的指令改为 unapplied（原因如 request_ended、delivery_failed），并修订消息和事件；同一事务锁串行化受理/consume/terminal。只有所属请求最终 completed 的已完成轮次才可进入以后 Context，unapplied 永不作为模型已用历史。现有 `UserInputInbox` 仍可做缓冲，但 Java 账本是去重和恢复的真源。

`display_view` 固定为 `{version:1, clarifying_question?, task_id?, operation_id?}` 白名单；文本字段及助手 content 均须限长、验证可显示编码；前端按纯文本转义显示。引用必须经当前用户、会话、任务/操作归属校验。历史中不存完整卡片布局、旧审批 payload 或可执行能力。partial 是已落盘的阶段性安全文字，不是 token 流或浏览器已收到的证明；每次更新稳定 `message_id` 的 revision 并分配事件 sequence。`side_effect_status` 为 none/confirmed/unknown；调用可能写工程状态的工具前先将风险标为 unknown，只有按工作区/产物事实核实后才可改 confirmed。不能因 Python 取消异常推断 none。

## 5. 公共与内部接口草案

所有 URI/字段均是**拟议契约**，非现有路由。Java context-path 为 `/api`；公共路径写完整外部路径，仍用现有 token Header 与 `@CurrentUser`。内部路径相对 context-path，在私有网络上使用独立服务认证和传输保护，须从现有 `TokenInterceptor` 浏览器路由明确分离。除启动激活与票据消费外，AI→Java 的会话状态变更都携带可信 user_id、session_id、writer_epoch；启动激活由独占锁、deployment_id 与唯一 boot_id 限定，票据消费由独立服务认证限定。接口返回稳定 code，不凭客户端 user_id 或旧 epoch 写入。

### 5.1 Java 提供给前端

| 方法与路径 | 核心请求/返回 | 规则 |
| --- | --- | --- |
| POST /api/ai/sessions | session_id、title、created_at、state | 认证后创建并绑定用户。 |
| GET /api/ai/sessions?before=...&limit=20 | items、next_before、has_more | limit 最大 50；只列当前用户 active 会话。 |
| POST /api/ai/sessions/{session_id}/ws-ticket | ticket、expires_at | 重查登录/归属/active；单次消费。 |
| GET /api/ai/sessions/{session_id}/messages?before_sequence=...&creation_watermark=...&limit=50 | items、next_before_sequence、has_more、creation_watermark | 首次读取同一数据库快照确定水位 H，取创建序号不大于 H 的最新 limit 条；后续 `before_sequence` 排他地向更早消息翻页。只固定 `created_sequence <= H` 的集合，当前消息修订可以晚于 H；每页按 created_sequence 正序返回，limit 最大 100。 |
| GET /api/ai/sessions/{session_id}/events?after_sequence=...&limit=100 | items、next_sequence、has_more、high_water_cursor | after_sequence 排他；按 sequence 正序，limit 最大 200；next_sequence 为本页最后一条 sequence（空页则为输入游标）；含消息更新、指令终态及请求终态。 |
| GET /api/ai/sessions/{session_id}/requests/{request_id} | status、user_message_id、assistant_message_id、task_id、side_effect_status、error_code | 重连、ACK 丢失时查询，不触发重跑；追加指令由消息页/事件显示。 |
| DELETE /api/ai/sessions/{session_id} | 完成 204；清理中 202 + deletion_id | active 请求返回 409；重复删除幂等。GET /api/ai/sessions/{session_id}/deletion 查询进度（仍需登录与原用户归属）。 |

消息视图最小字段为 message_id、request_id、input_id(适用时)、role、content、status、revision、created_sequence、updated_sequence、created_at、display_view。事件最小字段为 event_id、sequence、request_id、input_id(适用时)、event_type、message_id、message_revision、message_view 或 safe_summary、created_at。错误统一含 code、message、request_id；401 未登录，跨用户一律 404，409 包含 session_busy/request_id_conflict/input_id_conflict/request_terminal，503 为账本不可用或 AI 未就绪。旧会话 ID 不重用。

### 5.2 Java 提供给 AI 的内部接口

| 方法与路径（相对 Java context-path） | 事务职责 |
| --- | --- |
| POST /internal/ai/ws-tickets/consume | 原子消费票据，返回 trusted_user_id、session_id、登录会话引用；校验有效期、归属、服务认证。 |
| POST /internal/ai/login-sessions/check | 按可信登录会话引用核验用户仍有效、会话归属；供连接周期检查与发送前检查，不回传浏览器 Token。 |
| POST /internal/ai/runtime/activate | AI 持锁时在共享根递增并落盘 lock_generation，再携 deployment_id、boot_id、lock_generation 调用；Java 只接受更大 generation 并返回 writer_epoch，当前 boot_id/generation 重试幂等，较旧 generation 拒绝；立即拒绝旧代次写入；完成遗留收敛前不得对外 ready。 |
| GET /internal/ai/runtime/active-requests?before=...&limit=... | 分页列出旧代次 accepted/running 及归属、可能副作用标志，供启动扫描。 |
| POST /internal/ai/sessions/{session_id}/requests/{request_id}/interrupt | 用新 epoch 将遗留请求置 interrupted、待处理指令置 unapplied，同事务产生终态事件；幂等。 |
| POST /internal/ai/sessions/{session_id}/requests/accept | 校验用户/登录/会话及同会话无活跃主请求；同事务写 ai_request、初始用户消息、pending 助手消息和事件。相同 digest 的重复请求返回原状态/ID，无模型重跑；不同 digest 409。提交前不得 ACK 或执行。 |
| POST /internal/ai/sessions/{session_id}/requests/{request_id}/running | accepted → running；重复幂等。 |
| POST /internal/ai/sessions/{session_id}/requests/{request_id}/steers/accept | 仅 chat 请求且仍 accepted/running；先查 (session_id,input_id) 的原 digest，再与 terminal 在同一请求行锁下受理；同事务写指令、用户消息和事件。重复返回原消息/当前状态，异 digest 409；终态后新 input_id 拒绝。 |
| POST /internal/ai/sessions/{session_id}/requests/{request_id}/steers/{input_id}/consume | queued → consumed，同时修订用户消息/写事件；必须在模型调用尝试前成功，终态后拒绝。 |
| POST /internal/ai/sessions/{session_id}/requests/{request_id}/effect-start | 可能写工程状态前把请求级 side_effect_status 置 unknown；重复提交幂等，账本提交失败不得调用该工具。首版不承诺单次工具调用恰好一次。 |
| POST /internal/ai/sessions/{session_id}/tasks/register | AI 先分配 task_id，创建工作区目录前向 Java 预登记；Java 校验 owner/session/request 归属，同 ID 幂等。登记失败不得创建本地目录，登记后创建失败由删除清理兜底。 |
| POST /internal/ai/sessions/{session_id}/requests/{request_id}/message-update | 更新同一个助手 message_id 的安全 partial、revision 与事件；终态或旧 epoch 拒绝。 |
| POST /internal/ai/sessions/{session_id}/requests/{request_id}/progress | 只写白名单 stage/safe_summary/安全引用；可选进度失败不广播，主任务可继续。 |
| POST /internal/ai/sessions/{session_id}/requests/{request_id}/terminal | 同事务写助手终态、请求终态、所有剩余 queued 指令的 unapplied 修订和事件；随终态提交 side_effect_status，confirmed 须有工作区/产物证据，否则保留 unknown；同终态幂等、异终态冲突；成功后才广播 final。 |
| GET /internal/ai/sessions/{session_id}/context?request_id=...&before_sequence=...&limit=100 | 按 created_sequence 倒序返回受理前已完成的同会话可见轮次及安全引用；排除 pending、unapplied、其他会话；返回 next_before_sequence、scan_truncated。AI 限量分页选取，不暗示已搜索未扫描记录。 |
| GET /internal/ai/sessions/{session_id}/requests/{request_id} | 返回既有状态、digest、消息/指令安全视图，供 ACK 丢失及重启核对。 |

AI 提供经服务认证的 `POST /internal/ai/sessions/{session_id}/cleanup`，请求含可信 owner_user_id、deletion_id；返回完成或可重试失败与安全分类计数。Java 不传任意文件路径；AI 按第 8 章的归属扫描与清单清理。该接口与 Java 账本**不是一个事务**。

### 5.3 AI WebSocket

路径保持 `/ws/sessions/{session_id}`。正式帧：`chat_start(type, request_id, prompt, ui_context, access_mode)`、`agent_command(type, request_id, command)`、`chat_steer(type, request_id, input_id, prompt)`、`chat_cancel(type, request_id)`。ID 由前端生成并在网络重试时保持不变；服务端在持久受理前校验 input_id 格式（8—80 位安全 ASCII，推荐浏览器 UUID）、prompt 长度（首版上限 20,000 字符）和每请求/队列配额，超限明确拒绝。`chat_steer` 仅可追加到同会话活动 chat 请求，不新建主请求、不改变权限。正式帧移除 `user_id`，不保留兼容授权。服务端在业务受理与发送持久事件前复验登录会话。

`chat_ack` 在 requests/accept 事务提交后发送，带 user/assistant message_id、event_id、sequence；重复主请求返回既有状态与 ID，不重跑。`chat_steer_ack` 在 steers/accept 提交后发送，带 input_id、message_id、revision、event_id、sequence、当前状态；丢 ACK 时同 input_id 重发得到同一记录。新 input_id 与 terminal 竞争，以 Java 请求行锁提交次序为准：先提交受理则进入历史，若终态先提交则拒绝；已受理但终态前未 consume 显示 unapplied。`chat_final` 只能在 terminal 提交后发送安全可见内容/版本化 display_view。未受理错误发稳定 code，不产生假 ACK；`chat_cancel_ack` 只表示取消信号受理，不能代替终态。

持久事件携带 event_id/sequence/message_id/revision（适用时）；非白名单 `agent_progress` 标为 transient，不给持久游标；白名单进度先提交再广播。`agent_debug` 不进入历史。示例仅示稳定字段；正文、时间和 ID 均为示例：

~~~json
[
  {"type":"chat_ack","session_id":"s_demo","request_id":"req_1","status":"accepted","user_message_id":"m_1","assistant_message_id":"m_2","event_id":"e_3","sequence":3},
  {"type":"chat_steer_ack","session_id":"s_demo","request_id":"req_1","input_id":"input_001","accepted":true,"status":"queued","message_id":"m_3","revision":1,"event_id":"e_4","sequence":4},
  {"type":"chat_final","session_id":"s_demo","request_id":"req_1","message_id":"m_2","revision":2,"event_id":"e_8","sequence":8,"response":{"status":"needs_clarification","message":"请确认边界条件。","display_view":{"version":1,"clarifying_question":"入口速度是多少？","task_id":"task_demo01"}}}
]
~~~

例如 H=5 时，m_2 在 H 前创建，终态更新于 sequence=8；晚到的消息页可返回 m_2 的 revision=2，事件补拉仍返回 sequence=8 的同一修订，前端不会重复或回退：

~~~json
{"creation_watermark":5,"items":[{"message_id":"m_2","request_id":"req_1","role":"assistant","content":"请确认边界条件。","status":"final","revision":2,"created_sequence":2,"updated_sequence":8,"display_view":{"version":1,"clarifying_question":"入口速度是多少？"}}]}
~~~

首次历史响应可包含晚于创建水位 H 的修订；事件从 H 后补拉，较低 revision 不覆盖较高 revision，后续旧消息分页也同理。HTTP 外层可用 Java 统一响应包装，内层字段语义须保持一致。

## 6. 状态机、幂等和故障语义

主请求：accepted → running → completed/failed/cancelled/interrupted；accepted 可直接进入取消/中断，终态不可回退。Java 用会话行锁/唯一约束保证同会话单活跃主请求，不能只靠 AI 内存。追加指令：queued → consumed 或 unapplied；请求终态前未消费的 queued 在终态事务内转 unapplied。用户消息保留其原文和真实状态，不把未采纳指令悄悄删掉。只有 completed 的已完成轮次进入后续 Context。

主请求幂等键为 (session_id, request_id)，指令键为 (session_id, input_id)。同键同 digest 返回原记录；不同 digest 409。即使 ACK 发送失败，也只能用原 ID 重试/查询，不得重新执行。`agent_command` digest 覆盖完整命令；Java 终态与工作区操作事实共同用于判断，不能把进程内 `_command_execution_records` 当跨重启证明。执行成功但 terminal 暂不可写时不发送成功 final、不自动重跑；核对产物后才决定可否收敛。

**首版单写者启动顺序**：明确配置持久、共享的工作区根；进程启动先对该根的独占锁文件取得 OS 排他锁，并持有到所有任务停稳/进程退出。部署副本数=1、worker 数=1；所有候选实例必须看见同一锁文件，文件系统必须可靠支持进程排他锁，否则拒绝部署。新实例未取得锁不能 ready，不允许重叠服务。取得锁后生成唯一 boot_id，在共享根递增并持久化 lock_generation，再调用 Java runtime/activate；当前 boot_id/generation 超时重试幂等，Java 只接受更大 generation、递增 writer_epoch 并拒绝旧代次变更；分页扫描所有旧代次 accepted/running，逐条置 interrupted、排队指令置 unapplied，直到再次扫描为空才开放 WS。扫描/Java 不可用则保持未就绪并重试/报错，不能永久放任 session_busy。旧进程仍存活时同一共享锁阻止新实例 ready；旧请求在途 HTTP 即使晚到也被 epoch 栅栏拒绝。禁止脱离持锁进程的后台执行者；外部命令/服务可能已有副作用，仍需事实核对。多 AI worker 需要另评 Java 租约、心跳/过期扫描和工具 fencing，不在首版放行。

可能写工程状态的工具在调用前提交请求级 effect-start，将 side_effect_status 置 unknown；重复提交幂等，不要求审批 operation_id 预先生成；取消、断连、登出或崩溃发生在此后，若无明确事实证明则 `side_effect_status=unknown`。即便进程被取消，也不得声称外部工具恰好执行一次。可核实任务/产物时才改 confirmed；无副作用路径保持 none。Java terminal、partial、progress、steer 状态写入须校验 writer_epoch 与非终态；旧写者不能覆盖 interrupted。

受理失败 → 不 ACK、不执行；持久受理成功但 ACK 丢失 → 原键查询/重试，执行是否继续以连接与当前状态为准；steer 入本地队列失败 → 尝试同请求恢复投递，仍失败则保持 queued，终态事务标为 unapplied，不伪称已采纳；取消/断连 → 通知运行时停止，待确认任务终止后写 cancelled，无法确认或崩溃写 interrupted；可选进度落盘失败 → 不广播；terminal 落盘失败 → 不发 final，重试或启动扫描收敛。Java 每个终态事务先于 WS 终态广播。删除中禁止新受理/事件写入。

## 7. 历史恢复与 Context 链路

**创建水位，不是内容快照**：首次历史查询在一个 Java 数据库快照中取得当前最大事件 sequence H，并据此选择 `created_sequence <= H` 的消息集合；后续分页携带 `creation_watermark=H`，只固定创建集合，不保证返回 H 时刻的旧 revision。分页期间发生的 partial/final 会让晚到页面携带较新 revision；若产品以后要求严格 as-of H，须由 Java 从事件快照重建，不能只查当前消息表。

前端打开会话：先取消息第一页和 H；建立带新票据的 WS 并暂存实时事件；从 `events?after_sequence=H` 连续补拉直到追平，再合并缓冲事件。以 event_id/sequence 去重，以 message_id 定位消息，只应用更高 revision；相同 revision 时以更高 updated_sequence 或稳定事件顺序去重，不用晚到旧页覆盖新内容。继续向上翻页时一直传最初 H。断线后重新拿票据并从已应用的连续事件游标补拉；游标不可用、服务端数据已删或本地状态不可信时重取第一页。游标只在连续处理成功后推进，不能因某个 WS 新事件跳过尚未补拉的序号。状态为 queued/unapplied 的追加指令必须可见，但 unapplied 不得显示为“已执行”。

历史卡片仅恢复安全文本、澄清问题、请求终态及校验后的 task_id/operation_id 引用；前端对 `display_view.version=1` 实施字段白名单，未知版本只显示文本与状态。**首版历史卡片均为只读**，审批、运行、继续执行按钮不从旧 payload 重建；要进行动作，必须进入当前任务界面，由实时任务状态和权限检查重新决定可用操作。当前 AI v1 `chat_final` 也只返回这份安全视图；若首版仍要展示可操作的实时卡片，前端与后端需另设实时任务入口，不通过旧快照直接触发工具或审批。

AI 对新请求只读取受理前已 completed 的本会话轮次，按近期性及确定性关键词/中文片段相关性选择旧轮次；请求原始用户文本和同请求实际 consumed 的追加指令按顺序投影，queued/unapplied 不进入后续历史 Context。完整历史由 Java 保存，不整体塞入 Prompt；短期 Memory、任务投影和当前 ui_context 仍通过 ContextPipeline → AgentContext → PromptContextBuilder，历史投影携带来源、会话、选取原因，不解析其他模块 Prompt 文本提取事实。Runtime 只用账本结果替换 `SessionMemory.recent_turns`，保留短期记忆构建的 `active_task` 和 `task_projection`；即使账本返回空轮次，也不能清除多轮澄清的当前任务状态。

模型调用前统一核算系统规则、当前请求/已消费追加指令、必要页面事实、近期与相关旧轮次、工具 schema、任务工具对话/结果及输出预留；模型上限由部署显式配置，现有 4,000/262,144 不能当总预算。优先保留系统规则、当前请求、必要页面事实，再保留近期轮次和相关旧轮次；超限先丢旧轮次、再压缩非关键页面列表，不拆散工具调用与结果配对。计数/压缩失败时确定性裁剪或拒绝，不发送已知超量输入。验收按配置的估算器上限计算，供应商 tokenizer 误差仍需记录；只记录数量、估算 token、裁剪原因与 trace ID，不落隐私正文。

## 8. 删除与保留

DELETE 先重查登录、用户归属与 session active；若有 accepted/running 主请求返回 409，提示取消并等待持久终态。Java 将会话置 deleting、分配 deletion_id 后拒绝新的受理与普通历史读取，但允许原用户查删除进度；调用 AI 清理，收到**完整成功**才删除 Java 展示消息、事件、请求/指令内容与可检索记忆，仅留不含正文的 tombstone/必要审计标识。AI 清理与 Java 数据库不构成原子事务；任一环节失败保持 deleting、返回 202 和可重试状态，不返回 204。重复 deletion_id 幂等，后台重试需记录阶段、耗时、错误类型及安全计数。

AI 清理按可信 (owner_user_id, session_id) 遍历 `.task_state/*` 全部目录，并与 Java `ai_session_task_ref` 交叉核对：task_id 在创建本地目录前预登记；已登记但未创建的目录按幂等空清理处理，未登记或缺少 task.json 的目录不能静默跳过。每个候选先验证 task_id、owner、session、state_root/artifact_root 真实路径和非符号链接，禁止让客户端传路径。缺失/损坏元数据、无法证明归属或清理失败的候选必须记为 incomplete 并阻断“删除完成”，交人工核对或补映射，不静默跳过。

| 数据类别 | 首版删除动作 |
| --- | --- |
| `.task_state/<task_id>/task.json` 中 goal、request_id 及技能快照 | 归属核验后删除整个该任务内部状态目录；若仍需无正文审计，只在 Java 留最小 tombstone，不保留 goal。 |
| `checkpoint.json` 与其中模型消息/工具结果 | 同上删除；其内容可能含完整会话/工具正文，不只清空可见聊天表。 |
| `assistant_messages.jsonl`、`events.jsonl` 和其他任务内部状态/工具缓存 | 同上删除；逐文件记录分类结果，新增状态文件默认视为待分类，不自动忽略。 |
| `.scene_approvals/<operation_id>.json` 的待审批/已审批快照 | 依据记录中的 user_id/session_id/task_id 扫描并核验；先在审批锁下使待审批操作失效，再删原始写入内容与快照。已审批快照也删，但已发布成果不回滚。 |
| 任务 `artifact_root` 下尚未发布的文件、临时结果 | 由场景服务证明该任务独占、未发布、未被场景正式引用后才删除任务专属目录；无法分类、服务不可用或路径共用时阻断完成，不按目录名盲删。 |
| 已发布到用户场景的工程文件 | 保留原权属与现有授权，不因聊天删除而删改；在前端删除确认文案中明确告知。 |

AI 清理接口返回各类别 deleted/retained/incomplete 的安全计数和错误码，不能回传正文或绝对路径。Java 以完成且 incomplete=0 为成功条件；若 Java 最终删库失败，可用同一 deletion_id 重试 AI 幂等清理。备份留存/彻底擦除期限待产品和运维确认；前端不能写“所有数据立即彻底销毁”。

场景服务掌握场景发布与引用关系，负责提供权威判定。接口须按可信用户、会话、任务、场景和具体产物绑定结果，并提供版本或等价并发控制，避免判定后又被发布或引用。目录位置、目录名和任务终态均不是发布证明；没有明确的未发布且未引用证明时 AI 返回 incomplete。接口与并发协议接通前，场景任务删除不能进入真实联调或生产验收。

## 9. 实施顺序、验证与三方交付

本次按“AI 后端先行、最小功能闭环”推进：AI 后端先为未决接口确定一版可验证的默认语义，完成 A、B 两阶段的设计、实现和本地验证；通过后整理接口字段、状态、错误码及测试样例，分别向 Java 后端和前端提出需求，再进入 C、D、E 阶段的真实实现和联调。AI 本地阶段使用假 Java、临时 SQLite/工作区与假模型，不声称三仓已实现；临时路径与假身份不可进入生产。真实部署约束和跨仓接口在联调时复核，不以前后端预先签核阻塞 AI 本地验证。

### 11.1 首版实施边界

### 11.2 必须在 AI 本地验收前闭环的逻辑问题

1. **旧激活请求反向栅栏新进程。** 若只按 boot_id 激活，旧进程迟到的首次请求可能让新进程的 writer_epoch 失效。第 4—6 章现已改为持有共享工作区独占锁时递增并持久化 lock_generation，Java 仅接受更大代次；同代次同 boot_id 重试幂等，较旧代次拒绝。AI 的假 Java 合同测试必须覆盖激活请求乱序、旧写者终态晚到及新进程启动收敛；测试通过前不能认定重启恢复闭环。
2. **无 task.json 的目录逃逸删除扫描。** 当前工作区创建过程可能先留下目录、后写元数据。第 4、5、8 章现已要求创建目录前预登记 task_id，并在删除时扫描全部任务状态目录、与登记引用交叉核对。AI 本地必须注入“登记后创建失败”和“目录已创建但元数据缺失”故障；无法证明归属或清理不完整时返回 incomplete，不能宣称删除完成。

以上两项是现稿已识别并修正的契约逻辑，仍须由 AI 实现和故障测试证明；不要求为此预先实现多写者租约、逐工具事务日志或完整工程产物自动对账。
