## 一页定位

| 能力层 | 当前已经实现或验证的边界 | 下一任务要补齐的边界 |
| --- | --- | --- |
| 会话记录 | 受信用户与会话下的请求、消息、追加指令、事件、分页、终态、删除契约；本地 SQLite/Fake Java 可验证重启与隔离 | 真实 Java PostgreSQL、真实票据与前端接入仍待三仓联调 |
| 会话 Context | 只从**同一会话**受理前已完成轮次选最近/相关历史；账本历史替换 `recent_turns`，保留短期任务投影 | 跨会话的用户事实/偏好提取、版本、冲突处理、检索与投影尚未实现 |
| 短期 Memory | `InMemorySessionMemoryStore` 按 `(user_id, session_id)` 存近期记录和任务事件 | 不是持久用户画像；进程重启丢失，不能作为长期偏好真源 |
| Skill | `SkillRuntime` 能发现仓库/任务工作区 Skill，按任务冻结快照，`skills.list/read/create/update/validate` 已接工具链 | 公共枚举虽有 `USER/SYSTEM`，实际用户级存储、权限、隔离、审核晋升与回退尚未接入 |

**关键区分**：会话账本保存“发生过什么”，用户记忆保存“经证据确认、对以后任务仍有用的事实或偏好”，Skill 保存“可复用的操作方法/资源”。不能把聊天原文、模型推测、用户偏好和可执行 Skill 混作同一种持久对象。

## 已落地链路及源码入口

1. **身份、受理与账本。** [`TrustedIdentity`、`ConversationLedger`、`HistoryTurn`、`LedgerMessage/Event/Request`](../../sftg_ai_backend/src/shaofeng_ai_backend/contracts/conversation_ledger.py) 是当前结构化边界。正式 v1 WS 业务帧不含 `user_id`；连接票据产生受信身份。[`ConversationSessionService`](../../sftg_ai_backend/src/shaofeng_ai_backend/application/runtime/conversation_session.py) 先在账本中受理，才让网关发 ACK/执行；同 ID 同 digest 复用原结果，异内容冲突。同会话只允许一个活跃主请求，`chat_steer` 有 `queued/consumed/unapplied`。[`ws_v1.py`](../../sftg_ai_backend/src/shaofeng_ai_backend/presentation/fastapi_gateway/ws_v1.py) 负责票据握手、传输和公开进度。
2. **本地持久验证。** [`LocalConversationLedger`](../../sftg_ai_backend/src/shaofeng_ai_backend/integrations/local/conversation_ledger.py) 用 SQLite 事务模拟 Java 账本；[`WriterGuard`](../../sftg_ai_backend/src/shaofeng_ai_backend/application/runtime/writer_guard.py) 用共享根独占锁、generation、writer epoch 处理重启旧写者；[`SessionWorkspaceCleaner`](../../sftg_ai_backend/src/shaofeng_ai_backend/application/runtime/session_cleanup.py) 核对任务登记与本地目录。`local`/`mock_java` 仅允许回环调试；[网关启动装配](../../sftg_ai_backend/src/shaofeng_ai_backend/presentation/fastapi_gateway/application.py) 对缺少真实 Java 适配器的 `production` 模式直接拒绝启动。
3. **历史进入模型。** [`completed_turns`](../../sftg_ai_backend/src/shaofeng_ai_backend/integrations/local/conversation_ledger.py) 只取本会话、当前受理之前的 `completed` 请求，合入已 `consumed` 的追加文本，不纳入 `queued/unapplied`。[`HistorySelector`](../../sftg_ai_backend/src/shaofeng_ai_backend/application/context/history_selection.py) 至多选 4 个最近轮次、再选 4 个有关键词/中文二字片段交集的旧轮次；这不是跨会话语义检索。[`RuntimeCoordinator`](../../sftg_ai_backend/src/shaofeng_ai_backend/application/runtime/runtime_coordinator.py) 只替换 `SessionMemory.recent_turns`，保留 `active_task/task_projection`；[`ContextPipeline`](../../sftg_ai_backend/src/shaofeng_ai_backend/application/context/pipeline.py) 和 [`PromptContextBuilder`](../../sftg_ai_backend/src/shaofeng_ai_backend/application/context/prompt_context.py) 继续负责标准化、受控摘要与预算裁剪。
4. **Skill 运行时。** [`SkillSourceKind`](../../sftg_ai_backend/src/shaofeng_ai_backend/contracts/skills.py) 包含 `SYSTEM/REPOSITORY/USER/WORKSPACE/EXECUTOR`，但[`SkillRuntime.create_snapshot`](../../sftg_ai_backend/src/shaofeng_ai_backend/application/skills/skill_runtime.py) 当前实际扫描的是配置根目录和任务工作区 `.agents/skills`，归类为 `REPOSITORY/WORKSPACE`。任务快照带包指纹，正文按需通过 `skills.read` 读取。当前[`SkillAuthoringManager`](../../sftg_ai_backend/src/shaofeng_ai_backend/application/skills/skill_authoring.py) 只在一个授权根目录中创建/更新 Skill；[`skills.create/update`](../../sftg_ai_backend/src/shaofeng_ai_backend/application/tools/skill_tools.py) 是有策略门禁的中风险工具，但没有“为某个用户私有创建”或“晋升为全局系统 Skill”的所有权流程。

现有本地设计与跨仓接口待办分别见[AI 本地实现设计](../../sftg_ai_backend/docs/AI_CONVERSATION_LEDGER_LOCAL_DESIGN.md)和[Java/前端移交草案](../../sftg_ai_backend/docs/AI_CONVERSATION_HANDOFF_DRAFT.md)。旧的三仓现状核查写于 10 月 29 日，其中“无持久会话账本/无历史选择”等描述不能再当作当前工作区状态。

## 新任务建议边界（待评审，不是现有协议）

### A. 持续收集用户事实与偏好

建议把“候选发现”和“确认落盘”分开：模型可以从**已持久、已完成且归属可信用户**的会话中提出候选；程序负责来源校验、分类、去重、冲突处理、可见性和写入。每条记录至少需要 `owner_user_id`、类型（事实/显式偏好/观察性偏好）、结构化值、来源 `session_id/request_id/message_id`、证据时间、确认状态、有效期或失效状态、版本与更新时间。用户显式更正应能压过旧推断；仅一次对话中的临时工程参数不能自动成为长期偏好。

现有 `ConversationLedger.completed_turns(identity, before_sequence, limit)` 仅查询当前 `session_id`；它不能枚举某用户的全部会话或提供跨会话抽取水位。若要后台持续收集，需由账本真源提供按可信用户和会话范围授权的增量读取/变更事件契约，并明确重试游标与删除通知；不能遍历本地 SQLite 内部状态或假定一次请求的 100 条候选覆盖用户历史。

建议先区分作用域：**用户级**跨本人会话复用，**会话/任务级**只对当前目标有效，**系统级**不承载单个用户私密事实。读取时先确定可信 `owner_user_id`，再按任务相关性、有效性、证据强度和预算选取有限条目，经 Context 公共契约进入 `PromptContextBuilder`；不要让 Capability 或 Skill 直接查聊天表、解析 Prompt，或把完整用户历史塞进模型。长期存储可由 Java/AI 的新端口负责，但其真源、事务和删除编排需与现有 Java 会话账本所有权一起评审，不能默认复用本地 SQLite 或短期 Memory。

为避免“更了解用户”变成不可核验的暗箱，建议提供用户可查看、更正、删除、拒绝某条候选的能力，并保留不含敏感正文的提取/采纳审计。会话删除、账号删除、偏好单独删除的级联语义需先定：例如一条偏好引用被删除的唯一证据时，是失效、脱敏保留还是先补其他证据。任何路径都应避免跨用户读写和因旧索引返回已删除内容。

### B. 多用户 Skill 与系统 Skill 转换

建议把所有权和发布状态做成显式事实：用户私有 Skill 绑定可信 `owner_user_id`；系统 Skill 由受控管理员/审核流程发布，面向指定租户或所有用户可见；仓库/工作区 Skill 继续保持现有语义。发现、读取、更新、调用均校验来源及 owner，`package` 只作为不透明引用，不能以客户端路径或可伪造的 `user_id` 决定授权。同名冲突必须有稳定解析规则；任务快照仍需冻结确切版本和完整包指纹。

建议的能力沉淀流程是“会话或实践证据 → 候选 Skill → 用户私有草稿 → 校验与试运行 → 人工审核/授权晋升 → 不可变系统版本 → 回退或撤下”。转换工具应复制或发布一个带来源关系的新版本，不直接把用户私有目录改标为 `SYSTEM`；需确认原创者授权、剔除用户身份/密钥/场景路径等私密内容、检查脚本依赖与 ToolPolicy，并记录原 Skill/版本、审核人、发布时间和结果。Skill 正文始终是不可信内容；晋升不赋予脚本或工具额外执行权限。首版可先完成用户私有隔离、版本和人工发布，再讨论自动发现候选。

这两条链路有关联，但不应互相代替：用户偏好是可更新的用户事实；Skill 是经过验证的操作能力。可以用用户偏好影响“给本人推荐哪些 Skill”，不能把某人的偏好正文自动做成全局系统 Skill。

## 推荐实施顺序与交接验收

| 步骤 | 具体交付 | 最小验收 |
| --- | --- | --- |
| 1. 冻结数据归属 | 与 Runtime、Context、Skill、Java 负责人确认用户记忆真源、认证来源、删除级联、Skill 可见范围与晋升权限；形成强类型公共契约 | 每个字段有来源、owner、可空性、生命周期；旧会话账本无需承担画像或 Skill 写入 |
| 2. 用户记忆闭环 | 从已完成会话提候选、确定性校验/写入、本人查看更正删除、有限检索和 Context 投影 | 两用户同名偏好隔离；显式更正覆盖旧推断；删除/冲突/重试后无幽灵记忆；预算和来源诊断可查 |
| 3. 私有 Skill 闭环 | 注入按身份授权的 Skill 来源和存储，扩展快照/读取/写入校验 | A 用户看不到 B 用户目录/正文；同名来源可区分；任务恢复检测版本漂移；模型传路径不能越权 |
| 4. 能力晋升工具 | 草稿校验、敏感信息检查、审核授权、不可变系统版本、撤回/回退 | 未审核不能发布；发布后私有源更新不暗改系统版；撤下后新任务不见，旧任务按明确恢复策略处理 |
| 5. 三仓联调 | 真实 Java 身份/持久存储、前端管理界面、AI Context/Skill 链路 | 重启/跨会话复用、跨用户越权、删除传播、重复操作幂等、审计事件脱敏与版本可追溯 |

## 需要明确评审的决定

1. **用户记忆真源与隐私控制**：由哪个服务持久化，是否允许从历史自动提取，用户如何查看/关闭/纠正，账号及会话删除如何传播，保留/备份期限是什么。
2. **偏好语义**：显式声明与推断的优先级、冲突/过期规则、跨会话适用范围、哪些工程事实只属于任务而不得提升到用户级。
3. **Skill 所有权与发布权**：用户私有、组织共享、系统全局的目标范围；谁能晋升/撤回；是否需要原作者同意；旧任务快照在系统版撤回后如何恢复。
4. **跨模块协议评审**：Context 负责人评审记忆提取与投影；Skill 负责人评审多来源发现/快照/写入；Runtime/Agent 负责人评审身份、状态、ToolPolicy 与观测；Java/前端负责人评审真实持久化和用户管理界面。正式跨仓接口经真实联调后再冻结。
