## 流程

### 用户发送：“你好，请简要说明你能帮我做什么。”
🟡<span style="background-color: yellow;">src > shaofeng_ai_backend > presentation > fastapi_gateway > application.py > ws_session > _run_agent_request</span>

- _run_agent_request 是 ws_session 内部定义的异步函数，用来在后台处理一条 WebSocket 请求。
- 由 asyncio.create_task() 启动，避免处理模型请求时阻塞 WebSocket 接收循环；这样服务仍能接收取消消息。
- 这个函数主要负责：
    1. 将原始字典校验成自然语言请求或结构化命令。
    2. 校验通过后发送 chat_ack。
    3. 调用 RuntimeCoordinator 执行请求。
    4. 清理运行时和 WebSocket 连接中的任务登记。
    成功执行时，之后的代码会把 Coordinator 返回的结果作为 chat_final 发回前端；
- 输入：前端发送的 JSON 消息转换成的字典
- 返回值是 None。函数不把响应对象 return 给 WebSocket 接收循环，而是通过 _safe_send_json() 把 chat_ack、chat_final 或 chat_error 等消息直接发给前端。

#### 1. 输入校验和 ACK 阶段
```python
        # 取得请求标识和消息类型
        request_id = str(ws_message["request_id"])
        msg_type = str(ws_message.get("type") or "")
        try:
            # 根据消息类型校验信封
            message = (
                ChatStartMessage.model_validate(ws_message)
                if msg_type == "chat_start"
                else AgentCommandMessage.model_validate(ws_message)
            )
        # 校验失败时发送错误并清理任务登记
        except ValidationError as exc:
            await _safe_send_json(
                {
                    "type": "chat_error",
                    "request_id": request_id,
                    "session_id": session_id,
                    "message": f"invalid {msg_type} message: {exc}",
                }
            )
            coordinator.finish_request(request_id, session_id=session_id)
            await _pop_active_task(request_id, asyncio.current_task())
            active_tasks.pop(request_id, None)
            return
        # 发送 chat_ack
        ack_sent = await _safe_send_json(
            {
                "type": "chat_ack",
                "request_id": request_id,
                "session_id": session_id,
                "status": "accepted",
            }
        )
```
- request_id 用于关联这条请求的进度、取消操作和最终响应。
- msg_type 表示请求类型，例如 chat_start 或 agent_command。如果字段不存在或值为空，就得到空字符串。
- 正常路径中，外层 ws_session 会在启动后台任务前调用 coordinator.ensure_request()，并将生成或确认过的 request_id 写回 ws_message，因此这里通常能取到该字段。

- msg_type 恰好等于 "chat_start" 时，使用 ChatStartMessage 校验；其他情况使用 AgentCommandMessage 校验。
- session_id 来自 WebSocket URL /ws/sessions/{session_id}，不要求放在消息信封里。

- 如果字段缺失、类型不符或多传了不允许的字段，Pydantic 会抛出 ValidationError。函数尝试发送 chat_error，其中包含请求 ID、会话 ID 和校验错误。
- 随后清理三处状态：
    - finish_request(...) 清除 Coordinator 中的请求取消状态。校验失败发生在真正调用 Coordinator 处理请求之前，所以这里必须主动清理。
    - _pop_active_task(...) 从全局活动任务表中移除这条任务。传入 asyncio.current_task() 可以避免旧任务误删同一标识下其他任务的登记。
    - active_tasks.pop(...) 从当前 WebSocket 连接的本地任务表移除记录。
清理后 return，这条无效请求不会继续执行，也不会调用模型。

- 校验通过后，后端通过 WebSocket 发出 ACK（确认消息）。如果发送成功，ack_sent 为 True。


🟡 ws_session > _safe_send_json
- _safe_send_json 是 ws_session 内部定义的异步辅助函数，负责向当前 WebSocket 连接发送一条 JSON 消息，并把“连接已关闭”转换成布尔结果。
- 输入 payload：准备发给前端的字典
    - 输出 bool：- True：websocket.send_json(payload) 没有遇到这里捕获的断连异常。
    - False：函数已知道连接关闭，或者这次发送发现连接已断开。
```python
        # nonlocal 表示这里会读取并修改那个外层变量，让后续调用也知道连接已经关闭。每个 WebSocket 会话各自拥有的状态。它在连接建立后初始化为 False，不是全局状态。
        nonlocal connection_closed
        # 此前已发现连接关闭，就不再尝试发送，直接返回 False。这可以避免后台任务继续反复向已断开的连接写消息。
        if connection_closed:
            return False
        try:
            # 字典编码为 JSON 并写到当前 WebSocket。await 期间当前协程会让出执行权；发送调用正常返回后，这个函数返回 True。
            await websocket.send_json(payload)
            return True
        except (RuntimeError, WebSocketDisconnect):
            # 只捕获这两类异常
            connection_closed = True # 后续调用会跳过发送
            logger.info("ws send skipped after disconnect session=%s", session_id) #记录会话级别的信息日志；这里没有把完整 payload 写进日志。
            return False
```


#### 2. 把自然语言请求交给 RuntimeCoordinator 执行
```python
    if not ack_sent:

        coordinator.finish_request(request_id, session_id=session_id)
        await _pop_active_task(request_id, asyncio.current_task())
        active_tasks.pop(request_id, None)
        return
    try:
        # 把校验通过的自然语言消息交给 RuntimeCoordinator.run_chat_entry()
        response = (
            await coordinator.run_chat_entry(
                session_id=session_id,
                user_id=message.user_id,
                prompt=message.prompt,
                ui_context=message.ui_context,
                request_id=request_id,
            )
        )
```
- ack_sent 是上一步 _safe_send_json() 的返回值。若它为 False，说明服务端已知道 WebSocket 连接关闭，或刚才发送 ACK 时发现连接断开。
- ACK 无法发送时，代码会清理请求状态：
    - finish_request(...)：清除 Coordinator 中该请求的取消状态。
    - _pop_active_task(...)：从全局活动任务表中移除当前后台任务。asyncio.current_task() 指当前执行这段代码的 asyncio 任务。
    - active_tasks.pop(...)：从当前 WebSocket 连接的本地活动任务表中移除该请求。
    - return：立即结束 _run_agent_request，不继续调用模型或处理业务。
- run_chat_entry() 的返回类型是 AgentResponse。它会进入后端的 Context 和 Agent 流程；完成后，当前函数后续代码会把 response 转成 WebSocket 可发送的数据并发出 chat_final。

🟡<span style="background-color: yellow;">src > shaofeng_ai_backend > application > runtime > runtime_coordinator.py > RuntimeCoordinator > run_chat_entry</span>

- 输入：session_id、user_id、prompt、可选的 ui_context、可选的 request_id。
- 输出：AgentResponse，即 Agent 处理完这轮请求后的结构化响应。
- 作用：登记请求生命周期，调用 _run_chat_agent_request() 执行自然语言请求，并在执行结束后清理取消状态。
- 注意：这个函数是异步的。finally 中的清理会在请求正常返回、抛出异常或协程被取消时执行。


🟡 RuntimeCoordinator > ensure_request

- 确保请求有 ID，并在取消状态表中登记该请求。
- 输入：可选的 request_id，以及可选的 session_id。
- 输出：标准化后的请求 ID 字符串 rid。
- 作用：若请求 ID 为空或只有空格，就生成一个新 ID；然后登记“尚未取消”的状态。
- 注意：它只在状态表中还没有该请求时写入 False。如果同一请求此前已被标记取消，它不会把状态重新改成未取消。在这条实际链路里，网关通常已先调用过一次 ensure_request()。因此 run_chat_entry() 里再次调用它时，是对同一请求的幂等登记；不能重置已有取消状态。
```python
        rid = (request_id or "").strip() or f"req_{uuid.uuid4().hex}" #如果结果仍为空，就生成类似 req_ 加随机十六进制字符的 ID。
        scope_key = self._request_scope_key(rid, session_id) # 用标准化后的请求 ID 和会话 ID 计算内部取消状态键。
        # 只在状态表中没有这个键时，登记 False，表示当前没有取消请求，然后返回请求 ID。
        # 若此前已被标记为 True，这里会保留 True，避免一次重复登记抹掉已经到达的取消信号。
        if scope_key not in self._request_cancel_map:
            self._request_cancel_map[scope_key] = False
        return rid
```


🟡 RuntimeCoordinator > _request_scope_key

- 静态辅助函数，不依赖实例状态。
- 输入：request_id 和可选的 session_id。
- 输出：取消状态表使用的内部键字符串。
- 作用：将请求 ID 按会话划分作用域，避免两个会话恰好用了相同的 request_id 时互相影响。没有会话 ID 时，键仍使用原请求 ID。
- 注意：函数会去掉两者首尾空格。\x00 是字符串中的 NUL 分隔符，用于区分会话 ID 和请求 ID。
```python
        rid = request_id.strip()
        sid = (session_id or "").strip()
        return f"{sid}\x00{rid}" if sid else rid
```
