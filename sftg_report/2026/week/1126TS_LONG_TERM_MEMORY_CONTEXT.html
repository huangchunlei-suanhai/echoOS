先统一术语：来源、衍生物、运行时视图各不相同

协作证据 / 会话档案
天枢记录的消息、操作、事件和回执，证明交互曾发生；用户或模型陈述不自动成为工程事实。
工程事实 / 工程现场
外部权威系统持有的资产版本、当前状态、验证结果与权限；天枢按稳定 ID 和版本读取。
任务状态
由账本事件、工作区结构化状态归约的续接视图，回答“任务走到哪”；不代表资产当前真值。
记忆候选
带来源、适用范围和待确认状态的提议。候选不等于生效记忆，绝不自动参与召回。
用户记忆
经用户确认、限定 owner 和场景、可撤回的个人可复用信息；不能授予工程访问权。
知识资产
经适格责任人发布、带证据版本和适用范围的复用结论；跨用户发布是独立受控流程。
当前上下文 / 投影
本轮从已授权、有效来源按预算组装给模型的一次性视图，不是新的永久事实库。
来源引用 / 依赖
指向 session/request 或外部 source_id/version 的可追溯关系，用于权限复核、更新失效和删除传播。
记忆是受治理的衍生物；知识是受控发布物；上下文只是本轮投影

评审红线：任何阶段都不能突破

不能把协作记录当工程真值模型回答、本地场景目录、Fake Java 和本地验证结果都不能冒充生产资产版本或权威验证。
不能让候选绕过确认待确认、冲突、过期、证据未知或失效的记忆与知识不得注入模型。
不能用个人记忆越权先核对身份和外部资产 ACL，再核对记忆／知识自身的 owner、scope 与发布范围。
不能让旧工程结论永久有效外部版本、验证状态或权限变化必须触发依赖失效；事件丢失要靠游标补拉与对账。
不能由模型裁决相互矛盾的工程结论冲突组隔离；工程事实回权威源，工程结论交场景责任人，个人偏好交用户。
不能把删除停在会话正文候选、记忆证据、摘要、索引、缓存、任务状态及备份恢复墓碑都须纳入可核验清理。
这些是目标架构的不可变约束；数据库、检索引擎、事件传输和部署拓扑可以按实际条件调整。
每次读、写、召回、发布、删除都要能解释来源、权限、版本与责任人

先定外部权威系统必须提供什么，不预设服务名称

资产与验证读取

稳定引用 + 当前版本

按 source_id / asset_id 返回版本、状态、更新时间、删除标记与验证结果；验证结果含基线、输入版本、结果 ID、结论状态和时间。天枢只保存受控引用及必要回执。

授权判断

以当前用户与场景核验

支持资产读取、结果引用与工程写入的分项权限检查。未知、超时或撤权按拒绝处理；天枢的 owner / scope 规则仍需独立检查。

变化通知

事件 + 游标 + 补偿查询

版本变化、验证撤回、删除、权限变化须可按游标增量拉取；事件至少含源 ID、版本、类型、时间和去重 ID。周期性对账补足漏事件。

写入与故障语义

幂等回执 + 明确未知态

工程写入由外部系统确认并返回操作 ID 与版本；超时不能推断成功或失败。接口区分无权、不存在、版本冲突、暂不可用，并设超时与熔断。

哪个现有服务承载这些能力，待资产／验证团队确认。可以由多个现有服务提供，但对天枢必须呈现统一的适配契约和权威归属。
真值责任与能力契约先于服务选型；不新建独立“工程真值服务”作为前提

会话记录、记忆与知识：三类信息按规则流转

01 · 留存天枢写入会话账本用户消息、Agent 响应、事件
02 · 筛选识别可沉淀内容明示偏好、决策、已验证经验
03 · 候选附证据和适用范围模型只提议，规则校验
04 · 复核用户或场景责任人确认按记忆类型确定责任主体
05 · 复用授权后有限召回来源变化时重新复核

记忆候选

由会话证据或外部验证引用生成；保留 claim、scope、evidence_ref、版本和责任人。

知识候选

首期留在用户＋场景隔离；跨用户共享必须经过单独受控发布，不自动升级。

目标：从稳定证据生成候选，人工确认后才激活；候选不进入召回。当前基础版仅在成功请求出现“请记住：”前缀时提出个人偏好候选，用户确认后生效；通用异步抽取与 Outbox 尚待建设。

记录是证据；候选是待判断的派生物；知识发布是独立治理动作04

责任人轻量复核

准确、有效、持续更新：把证据和状态都存下来

来源稳定引用session/request 或 asset/version
候选待确认owner、scope、有效期
激活证据与责任人确认冲突对象不进入召回
复核源更新时联动版本、权限、时效变化
退出替代、过期或删除索引、缓存同步清理
准确模型可提议；程序校验来源、状态、范围；适格责任人确认后才激活。
有效召回时重验权限、源版本、场景适用性和有效期；过期即不注入。
持续更新变更事件驱动复核；保留版本、裁决理由、撤回时间和来源链。
治理机制降低错误与过期风险；无法保证模型提议绝对正确，因此保留复核、撤回与追溯06

冲突如何收敛：按冲突类型交给对应责任人

工程事实冲突外部资产／验证源为准；必要时回源，天枢不裁决真值
工程结论冲突交该场景绑定的工程结论责任人；轻量确认，不走多级审批
个人偏好冲突提示用户选择或更新；新明确指令只覆盖适用范围

算法与人工的边界

算法自动处理完全重复去重；相同来源追加证据
↓ 发现语义矛盾
责任人裁决选择新版本、合并、冻结或废弃
↓ 无裁决前
冲突集隔离整组不召回，不由 LLM 选边
动作定义合并＝结论兼容且证据可并存；覆盖＝同一责任域新版本经确认替代旧版；冻结＝证据争议或权威状态未明；归档＝已被取代、撤回或不再适用。

同一 subject / scope 的矛盾结论归入同一冲突组，组内全部停止召回，裁决后只保留一组可生效版本及证据链。场景目录轻量绑定结论责任人；管理员处理流程故障，不代替工程裁决。

待裁决冲突先隔离；重复结论可以自动合并，矛盾结论不自动覆盖07

每层都通过授权

允许读取并按范围组装

外部适配器校验工程资产 ACL；知识检索校验发布范围；记忆检索校验 owner_user_id 与 scene_id。注入前再次核对。

身份 → 源权限 → scope → 版本 → 上下文
成员权限
撤销→
无权、越界或状态未知

拒绝检索与上下文注入

拒绝 / 未知 → 不展开、不投影

个人记忆不授予工程访问权；ACL 是检索和投影链路上的硬门槛08
09

长任务上下文：预算不足时按规则压缩和舍弃

先保留本轮目标、硬约束、当前焦点资产和未完成阻塞；历史越长，越依赖摘要与引用而非把全文反复塞入模型。预算策略是目标机制；数值按所用模型窗口配置
硬预算系统规则与本轮请求不因裁剪而丢弃
优先保留当前任务状态目标、阻塞、最近进展
按需取源现场与验证证据只读有权且当前版本
预算递减知识 → 用户记忆摘要、引用、降级召回
仍然超限删历史低优先项必要时拆任务或暂停

裁剪顺序

去重 → 截断工具观察 → 低优先项改摘要／引用 → 移除历史会话摘要 → 放弃低相关记忆。

不可裁剪项

当前用户请求、安全规则、必要权限条件、活动任务关键状态；必要信息放不下就不调用模型。

排序原则只在“已授权且仍有效”的候选中执行：当前工程证据 > 已发布且适用的知识 > 用户记忆 > 历史会话摘要。现有 PromptContext 默认 4,000 估算 tokens、预留 800；长对话压缩另有 262,144 窗口、90% 触发、预留 16,384、保留最近 8 条消息的配置，需按模型统一校准。

现有代码已有 token 估算、裁剪和长对话压缩；跨来源优先级策略仍需建设09

会话删除：默认清除由该会话衍生的个人信息

先封存将 session 标为 deleting，拒绝新读写并取消未完成提取任务
按依赖清理账本、任务续接状态、候选、摘要、向量、缓存和草稿
核验完成记录删除清单与结果；部分失败保持 deleting 并可重试
混合来源记忆与知识如何处理？

记忆先移除被删会话的证据并隔离；只有独立证据重新校验、责任人确认后才恢复。知识草稿删除；已发布知识若引用该会话则先下架复核，只有独立合规证据获批后才能保留。

1 · 请求身份校验＋幂等删除 ID由天枢处理会话数据删除
2 · 依赖图枚举该 session 派生物账本、候选、任务态、索引
3 · 混合来源移除本会话证据并隔离复核前不得继续召回
4 · 副本清缓存、索引、备份残留备份按删除墓碑到期重放
5 · 回执全部完成才标 deleted失败保留状态并可安全重试

会话删除不删除外部工程源资产；默认清除该会话衍生的个人信息。若还有其他会话或外部独立证据，目标规则是先隔离、复核后再恢复；全量个人信息删除另按用户级依赖图清理。

当前代码已有 deleting 重试和 SQLite 证据清理；多来源记忆仍可能保持 active，隔离复核与备份墓碑待建设10

票据撤销与账本恢复：先给出可讨论的服务目标

目标讨论基线；现行仅有单实例内存 ticket + Java 在线身份查询
主题建议默认发生异常时的动作
票据签发Java 保持平台登录与身份查询；天枢核验身份和会话归属后签发随机一次性 WS ticket，绑定 user、session、过期时间。无效、超时、跨会话或重复消费即拒绝；多实例时用共享原子消费存储。若未来改签名格式，再按 JWT BCP 限算法和受众。
入口有效期当前 ticket 默认 120 秒；目标建议继续控制在 2 分钟内单次消费。票据只用于建连，不代表工程 ACL。建连时复查 Java 登录态；后续工程动作另核外部权限和源版本。
撤销延迟目标讨论值：活动连接退出登录或封禁后 ≤ 60 秒停止新动作；当前 Java 身份短缓存 10 秒，但无已验证的连接级撤销 SLA。定期复核平台登录态，必要时接撤销通知；复核不可用则停止新工程副作用并关闭连接。
长任务续连任务按安全检查点持久化；重连时重新验证平台身份、会话归属、工程 ACL 与源版本。失效则暂停任务；不让已消费的 ticket 变成长期凭据。复核周期需按实际任务时长与撤销目标确定。
账本存储建议托管 PostgreSQL 多可用区、事务 Outbox、WAL／时间点恢复、加密备份。写入不可确认时不 ACK、不调用模型；通过 request_id 和幂等键恢复。
恢复目标灾备目标（故障域范围待定）：RPO ≤ 5 分钟，RTO ≤ 1 小时。恢复后校验 writer epoch／fencing，再从任务检查点续作，避免副作用重复。
60 秒与 RPO／RTO 是评审起点，不是现行 SLA 或行业统一值；需以威胁模型、部署拓扑和恢复演练定值。多可用区只覆盖部分故障域，区域级灾难需另配异地恢复。
Java：平台身份；天枢：WS ticket、会话账本、聊天记录与会话删除13

数据类型建议默认期限／触发到期动作说明

故障点可继续做什么必须停止什么恢复方式
资产／权限读取超时可显示明确标记为历史的引用，供用户查看。不把缓存当当前资产；不注入未经 ACL 确认的内容；不执行依赖当前状态的写操作。读请求有限重试＋熔断；权限未知一律拒绝。
验证系统不可用保留已完成的任务检查点并显示“验证状态未知”。不得宣称通过；不把本地验证替身结果冒充权威结果。验证任务异步重试／轮询；同一操作使用幂等 operation_id。
外部变更事件中断按事件游标恢复消费；周期性对账源版本。依赖版本超过对账水位或状态未知时，相关记忆先暂停召回。补拉事件、重建依赖索引、回放失效状态迁移。
天枢会话账本不可用可返回明确服务不可用状态。不 ACK 用户输入，不调用模型，不产生没有可追溯记录的副作用。幂等重试；Outbox 持久后再异步派发。
记忆服务不可用身份、账本和当前工程证据仍通过校验时，可按降级策略继续本轮。不声称已保存新记忆；不使用过期的本地缓存补齐。记录降级状态；候选以幂等任务补偿或提示用户重新提交。
登录态复核失败任务可保留已落盘检查点，不继续引用未知身份。拒绝新工程副作用并关闭连接。恢复平台登录后，由天枢重新签发建连 ticket；重新核验 ACL 和源版本。
建议：只对幂等读取做有限重试；写操作使用明确的操作 ID 和结果查询。超时代表“结果未知”时不得盲目重放。
